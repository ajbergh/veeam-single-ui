# Interface languages

Choose **Administration → Settings → Language & region**. Automatic mode follows the browser's language preferences. An explicit selection is saved in the `open-backup-ui-language` cookie for this browser. The server renders the same initial language as the client, including the document's `lang` attribute.

## Bundled languages

English (`en`), Spanish (`es`), German (`de`), Russian (`ru`), French (`fr`), Brazilian Portuguese (`pt-BR`), Simplified Chinese (`zh-CN`), Japanese (`ja`), Italian (`it`), Korean (`ko`), and Hindi (`hi`). German appears once in the selector.

Translations are JSON files in `lib/i18n/messages/`. Translation happens locally in the application; no translation provider, AI key, or external translation request is involved.

**Lens** is a feature name and must remain **Lens** in every language. Keep **Protection Lens** unchanged in navigation, breadcrumbs, headings, descriptions, and accessibility text; translate only the surrounding copy.

## Coverage

Localization covers navigation, breadcrumbs, shared grid/filter controls, connection screens and the feature showcase, application settings, and common labels across VBR, Microsoft 365, Veeam ONE, and administration views. The VBR overview, Job Operations, Capacity Watch, Capacity Forecast, Protection Topology, Ransomware Detection, Jobs & Policies table, Policy Profiles and their editors, Protected Data, and Virtual Inventory include widget descriptions, counts, statuses, menus, detail panels, and known application-authored diagnostics. The Lens selector and default-view controls use the same catalogs. Data Sources includes its table cells, status labels, investigation details, actions, dialogs, validation, counts, and application-authored connection diagnostics. Search hints across the app and shared dialog, theme, sidebar, pagination, and sorting controls use the same catalog.

The active Entra ID and Backup Copy creation forms include their steps, validation, loading states, and result messages. The AI health summary requests narrative content in the selected language and localizes its fixed section headings and status markers. Provider output and quoted diagnostics are not translated after generation. Route titles for Lens, topology, ransomware, Protected Data, and Virtual Inventory also follow the language preference.

Full VBR job and session investigations, workload/task drawers, retry chains, log controls, repository investigations, and the restore-point explorer (including its calendar and file details) use the catalogs. Microsoft 365 job/session, organization, repository, proxy, and protected-object recovery investigations include their shared facts, statuses, filters, known application diagnostics, and localized date/number formatting. Repository retention enums are decoded for display; raw resource names, vendor measurements, logs, and export data retain their source values.

The translation helper falls back to the English source text when a key is not present. Equal JSON key counts alone do not establish UI coverage: both the component's rendering path and its catalog entries must be localized. Source guards cover the migrated detail views and their shared presentation helpers; additional legacy views need the same explicit migration before they can be considered covered.

Veeam product names, user-customized section names, infrastructure/workload names, IDs, paths, and source API messages remain unchanged. Bundled screenshot pixels stay in their captured language. Date/number helpers use `Intl` with the selected locale; older views that format directly from the browser are not automatically rewritten.

## Adding or updating text

1. Use `useI18n()` from `components/providers/i18n-provider.tsx` in a client component.
2. Wrap interface copy with `t('English source text')`. For dynamic values use named placeholders, for example `t('{days} days remaining', { days: formatNumber(days) })`.
3. Add the exact source key and a translation to every locale JSON. Keep placeholder names unchanged. Do not concatenate translated fragments to construct sentences.
4. Keep model values and API payloads in their original form. Translate at the presentation boundary, not before filtering or submitting a request.
5. Run `npm run test:i18n`, `npm run i18n:audit -- --strict`, `npm run typecheck`, and the relevant UI checks. Review long German text and CJK layouts at narrow widths.

## Auditing coverage

- `npm run i18n:audit` summarizes registered translation keys and possible omissions by source file.
- `npm run i18n:audit -- --json` returns every finding with its source location for follow-up work.
- `npm run i18n:audit -- --strict` fails when a registered translation key is absent from the catalogs. The i18n tests also check key/placeholder parity and guard migrated Data Sources and VBR rendering paths, including explicit presentation registries.

Unwrapped-text findings are review candidates, not a count of confirmed missing translations. Technical values, product names, exported data, and upstream messages may correctly remain literal. Fix visible interface copy with explicit translation calls and named placeholders; never translate an entire DOM or arbitrary API values.

There are no automatically translated vendor logs or background sends to a translation service. Community review by native speakers is welcome.
